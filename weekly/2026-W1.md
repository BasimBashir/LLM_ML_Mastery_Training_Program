# Week 1 — Build your ML laboratory

## What I learned

- PyTorch tensors can run on the CPU or CUDA GPU; GPU operations are
  asynchronous, so benchmarks need warm-up and synchronization.
- `Dataset` defines how individual examples are retrieved, while `DataLoader`
  batches and delivers them. Batch size and worker count should be measured for
  the target workload.
- A training step runs a forward pass, computes loss, clears gradients,
  backpropagates, and updates parameters. Validation measures performance
  without updating weights, and complete checkpoints preserve training state.
- AdamW decouples weight decay from Adam's gradient update. Warmup, cosine
  scheduling, and gradient accumulation affect how optimizer updates are made.
- Autocast can use lower precision while keeping model parameters in FP32.
  FP16 uses gradient scaling; speed and memory benefits depend on the workload.

## Biggest debugging problem

### Problem

The FashionMNIST CNN stopped at the first training batch with
`AttributeError: 'typing.TypeVar' object has no attribute 'relu'`.

### Root cause

The script imported `F` from `torch.compiler`, not from PyTorch's neural
network functional API. The imported object therefore did not provide
`F.relu`.

### Fix

Imported `torch.nn.functional` as `F` and verified that the model's forward
pass returns ten class scores for each input image.

### Lesson

Imports with similar names can refer to unrelated APIs. Verify the imported
module as well as the model's expected input and output shapes. The full
FashionMNIST training run still needs to be rerun to confirm end-to-end
training.

## Experiment

### Hypothesis

The RTX 3090 should outperform the CPU on a large matrix multiplication, and
lower-precision training may improve throughput or memory use without
materially changing validation loss.

### Result

- One recorded matrix-multiplication run measured 0.339017 s on the CPU,
  0.011384 s on the GPU, 0.011688 s for GPU FP32, and 0.004662 s for GPU FP16.
  These are single-run timings, not a controlled benchmark.
- On the recorded AG News MLP run, FP32, FP16, and BF16 had similar validation
  loss (0.260619, 0.260584, and 0.260779). Measured allocated VRAM was 44.06 MB
  for each mode. FP16 was slower in that run and skipped five updates after
  non-finite gradients were detected.
- DataLoader and gradient-accumulation scripts support comparisons, but
  numeric results were not retained in their learning logs.

## What surprised me?

- Mixed precision did not improve measured speed or allocated memory for the
  small AG News MLP, despite similar validation loss.
- Correct CUDA timing requires explicit synchronization; otherwise the
  measured time may not include completed GPU work.
